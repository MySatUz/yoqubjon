# Формат файла для двухмодульного теста

Один `.tex` файл + настройки формы загрузки в админке. Парсер —
[`src/lib/texParser.ts`](src/lib/texParser.ts), раскладка по модулям —
[`src/lib/examModules.ts`](src/lib/examModules.ts), приём формы —
[`src/app/admin/actions.ts`](src/app/admin/actions.ts).

Документ самодостаточный: по нему можно написать валидный двухмодульный тест,
не открывая `TEX_FORMAT.md` (там тот же синтаксис вопроса, но без деталей про модули).

---

## 1. Минимальный скелет

```tex
% ── Модуль 1 ──────────────────────────────────────────────
\module{1}

\begin{question}
  \content{If \( x + 3 = 10 \), what is the value of \( x \)?}
  \options{
    A: 5
    B: 6
    C: 7
    D: 13
  }
  \answer{C}
\end{question}

\begin{question}
  \content{What is the value of \( 12 \times 8 \)?}
  \answer{96}
\end{question}

% ── Модуль 2 ──────────────────────────────────────────────
\module{2}

\begin{question}
  \content{The graph shows \( f(x) \). What is \( f(0) \)?}
  \image{graph-01.png}
  \options{
    A: \(-2\)
    B: \(0\)
    C: \(2\)
    D: \(4\)
  }
  \answer{B}
\end{question}
```

Всё, что вне `\begin{question}...\end{question}` и не является маркером модуля,
парсер игнорирует — преамбулу `\documentclass`, `\begin{document}` и прочее можно
оставлять или не писать вовсе.

---

## 2. Маркеры модулей

Парсер ищет ровно четыре токена верхнего уровня: блок вопроса и три вида маркеров.

| Маркер | Что делает |
|---|---|
| `\module{N}` | текущий модуль становится `N` (основная форма) |
| `\newmodule` | текущий модуль **+1** |
| `\begin{module}` | первый такой = модуль 1, каждый следующий = +1 |
| `\begin{module}[N]` | текущий модуль становится `N` |

`\end{module}` парсером не читается вовсе — его можно писать для читаемости, но
границу задаёт только `\begin{module}`.

Три эквивалентные записи одного и того же двухмодульного теста:

```tex
\module{1}
... 22 вопроса ...
\module{2}
... 22 вопроса ...
```

```tex
... 22 вопроса ...   % до первого маркера — это модуль 1
\newmodule
... 22 вопроса ...
```

```tex
\begin{module}
... 22 вопроса ...
\end{module}
\begin{module}
... 22 вопроса ...
\end{module}
```

Правила:

- Вопросы **до** первого маркера попадают в модуль 1.
- Маркер внутри `\begin{question}...\end{question}` маркером не считается — он
  часть тела вопроса и никуда не переключает.
- Номера модулей — от 1 подряд, **без пропусков**. `\module{1}` + `\module{3}`
  → ошибка `Module 2 has no questions...`.
- Диапазон 1…6 (`MAX_MODULE_COUNT`). Вне его → `Module number must be between 1 and 6`.
- Порядок маркеров произвольный, к одному модулю можно возвращаться:
  `\module{1} … \module{2} … \module{1}` валидно, вопросы просто дописываются
  в конец модуля 1. Читаемости ради так лучше не делать.
- Сквозная нумерация `order` в БД идёт 1…N по всему файлу; студенту номера
  показываются заново с 1 внутри каждого модуля.

## 3. Блок вопроса

```tex
\begin{question}
  \content{...}      % обязательно
  \image{file.png}   % необязательно
  \options{...}      % необязательно (нет → grid-in)
  \answer{...}       % обязательно
\end{question}
```

Порядок тегов внутри блока значения не имеет. Вложенные `{}` считаются
корректно, экранированные `\{` и `\}` за скобки не считаются.

### `\options{...}`

Каждый вариант — **с новой строки**. Метка `A`–`H` (регистр не важен) и
разделитель `:`, `.` или `)`; альтернатива — `\item[A]` или просто `\item`.

```tex
\options{
  A: Первый вариант
  B) \(x = 3\)
  C. Третий
  \item[D] Четвёртый
}
```

Текст варианта может занимать несколько строк — он тянется до следующей метки.
Два варианта в одной строке склеятся в один.

Вариантов должно быть **0 или ≥ 2**. Ровно один → ошибка.

### `\answer{...}`

- Для вопроса с вариантами: буква `A`–`H`. Буква за пределами числа вариантов
  (`\answer{D}` при трёх вариантах) → ошибка.
- Для grid-in (без `\options`): само значение — `96`, `12.5`, `\dfrac{292}{3}`.

### `\image{...}`

Имя файла точь-в-точь как у загружаемого изображения, с расширением.
Если файла нет среди загруженных → `Missing image for question N: file.png`.
До 5 МБ, только `png`, `jpeg`, `jpg`, `webp`.

---

## 4. Математика

Разделители: `\( … \)` (инлайн), `\[ … \]` (блок), `$ … $`, `$$ … $$`.
Незакрытый разделитель → ошибка ещё до KaTeX.

Каждая формула прогоняется через KaTeX (`throwOnError: true`, `strict: 'warn'`)
в `\content`, в каждом варианте и в `\answer`. Невалидная формула останавливает
загрузку всего теста с указанием номера вопроса и поля.

Таблицы — через `array` внутри `\[ … \]`, **не** `tabular`.

`%` начинает комментарий и убивает остаток строки. Литеральный процент — `\%`.

## 5. Что задаёт форма загрузки

В форме выбирается **Exam format**:

- **SAT modules** (`examFormat=modular`, значение по умолчанию) — по таймеру
  на модуль. Поля на каждый модуль: `questions` (1–200) и `minutes` (1–360).
  По умолчанию 2 модуля × 22 вопроса × 35 минут.
- **Single timer** (`single`) — один таймер `durationMinutes` на весь тест.

Как соединяются файл и форма:

| В файле | Формат в форме | Результат |
|---|---|---|
| есть маркеры | SAT modules | **разбиение берётся из файла**, поле «questions» игнорируется; время — из формы |
| есть маркеры | Single timer | ошибка: `The .tex file defines N modules. Switch the test format to SAT modules, or remove the \module markers.` |
| нет маркеров | SAT modules | вопросы режутся подряд по «questions» на модуль |
| нет маркеров | Single timer | обычный односекционный тест |

Тонкости разбиения без маркеров:

- **Последний модуль забирает весь остаток**, сколько бы ни было указано в его
  поле. 50 вопросов при настройке 22 + 22 → 22 и 28.
- Если вопросов не хватает на все модули (модулю досталось 0) → ошибка
  `The .tex file has N questions, which is not enough for M modules...`.

Тонкости времени при маркерах:

- Модулей в файле больше, чем строк времени в форме → недостающим модулям
  повторяется **последнее** указанное время (3 модуля в файле, 35 + 40 в форме
  → 35, 40, 40).
- Модулей в файле меньше → лишние строки времени отбрасываются.
- Сумма времени всех модулей ≤ 360 минут, иначе
  `Total test time must not exceed 360 minutes`.

---

## 6. Лимиты

| Параметр | Значение |
|---|---|
| Размер `.tex` | ≤ 2 МБ, расширение `.tex` |
| Модулей в тесте | 1–6 (`MAX_MODULE_COUNT`) |
| Вопросов на модуль (поле формы) | 1–200 |
| Минут на модуль | 1–360 |
| Суммарное время теста | ≤ 360 минут (6 ч) |
| Вариантов ответа | 0 (grid-in) или 2–8 |
| Метки вариантов и буква ответа | `A`–`H` |
| Изображение | ≤ 5 МБ, `png` / `jpeg` / `jpg` / `webp` |

---

## 7. Что проверяется перед сохранением

Загрузка падает целиком (частичного импорта не бывает), если:

1. у вопроса нет `\content{...}` или `\answer{...}`;
2. ровно один вариант в `\options{...}`;
3. буква ответа выходит за число вариантов;
4. не закрыт математический разделитель;
5. формула не собирается KaTeX;
6. номер модуля вне 1…6;
7. в нумерации модулей пропуск;
8. в файле маркеры, а в форме выбран Single timer;
9. вопросов не хватает на заданное число модулей;
10. суммарное время > 360 минут;
11. для `\image{...}` не загружен файл с таким именем;
12. в файле не найдено ни одного `\begin{question}`.

---

## 8. Как это видит студент

- У каждого модуля свой таймер; неизрасходованное время **не переносится**
  в следующий модуль.
- Между модулями — экран перехода: «Module 2 of 2», число вопросов и минут.
  Таймер стартует по кнопке.
- Вернуться в пройденный модуль нельзя.
- Нумерация вопросов в нижней навигации начинается с 1 в каждом модуле.
- Модуль, в котором в итоге не оказалось вопросов, просто не показывается.

---

## 9. Чек-лист перед загрузкой

- [ ] `\module{1}` и `\module{2}` стоят между блоками вопросов, а не внутри них
- [ ] у каждого вопроса есть `\content` и `\answer`
- [ ] у вопросов с вариантами их 2–8, каждый с новой строки, ответ — существующая буква
- [ ] grid-in идут без `\options`, в `\answer` — само значение
- [ ] имена в `\image{...}` совпадают с именами загружаемых файлов
- [ ] литеральные `%` записаны как `\%`
- [ ] в форме выбран **SAT modules** и проставлено время каждого модуля
